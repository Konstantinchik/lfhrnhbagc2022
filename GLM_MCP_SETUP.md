# Unity MCP: подключение клиента через stdio

Этот вариант запускает MCP-сервер непосредственно как дочерний процесс клиента. Не запускайте `start-mcp.ps1` и `npm run dev` как MCP-команду: это сценарии ручного запуска/разработки, не stdio-транспорт клиента.

## 1. Подготовка

Из корня проекта выполните:

```powershell
Set-Location -LiteralPath 'D:\PROJECTS\DarkTreeFPS2022\lfhrnhbagc2022\mcp-server'
npm ci
npm run build
```

Убедитесь, что Unity Editor запущен и MCP Bridge доступен на `localhost:7777` (по умолчанию). Не нужно отдельно запускать Node MCP-сервер в терминале — его запускает клиент.

## 2. Конфигурация клиента

Добавьте сервер `unity-editor` в конфигурацию MCP вашего клиента. Пример ниже использует распространённые поля `command`/`args`/`env`; если GLM использует собственную оболочку настроек или иной формат, перенесите в неё те же значения:

```json
{
  "mcpServers": {
    "unity-editor": {
      "command": "C:/Program Files/nodejs/node.exe",
      "args": [
        "D:/PROJECTS/DarkTreeFPS2022/lfhrnhbagc2022/mcp-server/dist/index.js"
      ],
      "env": {
        "UNITY_EDITOR_HOST": "localhost",
        "UNITY_EDITOR_PORT": "7777"
      }
    }
  }
}
```

Проверьте фактический путь к Node командой `where.exe node`. Если Node доступен через `PATH` в окружении клиента, можно указать `"command": "node"`; абсолютный путь обычно надёжнее для GUI-клиентов. Пути в JSON удобнее записывать с `/`.

Не указывайте `npm run dev`, `tsx watch`, `start-mcp.ps1` или отдельный терминал как серверную команду. MCP-клиент должен владеть процессом и обмениваться с ним JSON-RPC сообщениями по stdin/stdout.

## 3. Проверка подключения

1. Перезапустите или переподключите MCP-сервер в настройках клиента.
2. Убедитесь, что клиент обнаружил инструменты с префиксом `unity_`.
3. Вызовите `unity_check_connection`. Ожидаемый ответ содержит `"connected": true`.
4. Затем проверьте безопасное чтение `unity_get_scene_info`.

Если инструменты не появились, сначала проверьте ошибку запуска процесса в логах GLM: путь к `node.exe`, путь к `dist/index.js`, доступность процесса и поддержку GLM локальных MCP-серверов stdio. Если инструменты видны, но `unity_check_connection` возвращает false, проблема уже на участке MCP → Unity HTTP Bridge: проверьте Unity Bridge отдельно.

## 4. Переменные окружения

`UNITY_EDITOR_HOST` и `UNITY_EDITOR_PORT` передаются прямо клиентом. Дополнительно MCP-сервер загружает `mcp-server/.env` по пути относительно собственного файла, а не текущей рабочей папки клиента. Это устраняет типичный сбой, когда клиент запускает процесс с неожиданным working directory.

Шаблон настроек: `mcp-server/.env.example`. Секреты в конфигурацию не добавляйте; текущему мосту Unity API-ключ не требуется.

## Разделение двух процессов

- **MCP процесс:** запускается GLM/Codex/Claude как stdio child process — `node .../mcp-server/dist/index.js`.
- **Unity Bridge:** HTTP сервер внутри Unity Editor на `localhost:7777`.

Работа одного не означает, что работает другой. Инструменты MCP могут отображаться даже при закрытом Unity; в этом случае проверка соединения с Editor вернёт `connected: false`.
