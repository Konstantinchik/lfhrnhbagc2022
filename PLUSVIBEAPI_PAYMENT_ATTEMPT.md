# Попытка подключить оплату PlusVibeAPI к DeepAI Code

## Цель

Проверить, можно ли пополнять PlusVibeAPI и использовать его API для оплаты модели в текущей программе **DeepAI Code**, в которой ведётся этот чат и работа над проектом `lfhrnhbagc2022`.

## Краткий итог

По проверенным экранам **не удалось подтвердить, что баланс PlusVibeAPI может оплачивать текущую сессию DeepAI Code**. Кабинет PlusVibeAPI предлагает совместимые API-endpoint и конфиги для отдельных программ (например, Claude Code, Codex, Cursor, Cline, Pi), а DeepAI Code на показанных списках не указан.

В настройках DeepAI Code на скриншоте виден встроенный провайдер **DeepAI**, авторизованный аккаунтом пользователя. Не обнаружено подтверждения, что PlusVibeAPI подключён к этому провайдеру или что баланс PlusVibeAPI списывается за текущие запросы.

**Не следует пополнять PlusVibeAPI с ожиданием, что это автоматически продлит или оплатит данный чат.** Сначала нужно найти в DeepAI Code подтверждённую настройку стороннего/custom provider с полями API URL, ключа и модели либо получить подтверждение поддержки от службы поддержки приложения.

## Хронология и выводы по экранам

### 1. Кабинет PlusVibeAPI: API-ключи

На экране API-ключей были показаны:

- OpenAI-совместимый endpoint для России: `https://plusvibeapi.ru/v1`;
- альтернативный endpoint: `https://gw.plusvibeapi.ru/v1`;
- созданный API-ключ;
- баланс кабинета: **120,00 ₽**;
- предупреждение для нового аккаунта о временном лимите запросов.

Endpoint и API-ключ позволяют подключать совместимые клиенты, но сами по себе не переключают DeepAI Code на PlusVibeAPI.

> **Безопасность:** на присланных скриншотах API-ключ был виден. Его следует отозвать/удалить в PlusVibeAPI и создать новый. Не сохранять ключи в этом документе, чате, Git или скриншотах.

### 2. Страница «Подключение за минуту» PlusVibeAPI

На странице были варианты:

- «Общаться в приложении» — Claude Desktop, Cherry Studio;
- «Программировать в редакторе» — VS Code, Cursor, Cline, Kilo;
- «Агент в терминале» — Claude Code CLI или Codex CLI;
- «Подключить свою программу» — SDK или curl.

DeepAI Code прямо в списке не указан. Поэтому выбор «Подключить свою программу» мог бы быть полезен только при наличии в DeepAI Code поддержки пользовательского API-провайдера. Сам экран PlusVibeAPI не доказывает такую поддержку.

### 3. Дополнительный список интеграций

В секции готовых конфигураций PlusVibeAPI показаны, среди прочих:

- Claude Code;
- Codex CLI / Desktop;
- Cursor;
- Cline;
- Pi;
- OpenCode и другие агенты.

В списке есть **Pi**, но это не означает автоматически, что конфигурация подходит приложению DeepAI Code: необходимо проверить, позволяет ли DeepAI Code импортировать такой конфиг или задавать аналогичный custom provider. На скриншотах это не подтверждено.

### 4. Настройки DeepAI Code → Providers

На скриншоте настроек DeepAI Code виден встроенный провайдер **DeepAI**, состояние `Authenticated`, список включённых моделей и кнопка `Add custom model`. В показанной области нет полей стороннего API Base URL или ключа PlusVibeAPI.

Поэтому нельзя считать, что PlusVibeAPI уже подключён. Не следует нажимать `Sign out` у DeepAI ради проверки: это может отключить текущую авторизацию и не подключит PlusVibeAPI автоматически.

### 5. Usage → Tokens за 30 дней

На экране статистики было указано около **60,1 млн обработанных токенов** за выбранные 30 дней, в том числе:

- DeepAI — одна сессия, около 8,80 млн токенов;
- Codex — восемь сессий, около 51,3 млн токенов.

Также отдельно показаны cached input, uncached input и output. Это статистика использования токенов, не денежный баланс и не число оставшихся запросов. Экран был настроен на `All environments / All providers`, поэтому цифры нельзя отнести только к проекту `lfhrnhbagc2022` или конкретному чату.

### 6. Usage → Limits

На экране лимитов для DeepAI отображалось:

- **49 Theos** остатка;
- **100% left**;
- дневное выделение: 49 Theos;
- обновление примерно через 59 минут.

Это означает, что на момент снимка дневной лимит DeepAI не был израсходован. По одному экрану нельзя перевести Theos в количество запросов или токенов.

Для Codex интерфейс показал ошибку чтения usage: `JSON-RPC -32603`. Это ошибка получения статистики; она сама по себе не доказывает, что лимит Codex исчерпан.

### 7. Контекст текущего чата

В боковой панели DeepAI Code было показано `Context Window 42% · 133k/320k`. Это заполнение контекстного окна данного диалога, а не денежный баланс, не дневной лимит и не тариф.

### 8. Вопрос о GLM и MCP

Попытка ранее диагностировать MCP-сбой GLM относилась к подключению внешнего инструмента к проекту, а не к оплате текущего чата. Наличие модели GLM в статистике использования не означает, что PlusVibeAPI оплачивает эту сессию.

## Что можно сделать дальше

1. В настройках DeepAI Code проверить `Settings → Providers → Add provider` и выяснить, поддерживается ли провайдер типа **OpenAI-compatible / Custom** с настраиваемыми `Base URL`, API-ключом и ID модели.
2. Если такой провайдер поддерживается, запросить официальную инструкцию для DeepAI Code или проверить совместимость с документацией приложения. Только после этого тестировать подключение на безопасном минимальном запросе.
3. Если пользовательский endpoint в DeepAI Code не поддерживается, использовать PlusVibeAPI в одном из явно поддерживаемых приложений (например, Cursor, Cline, Claude Code CLI, Codex CLI или совместимом Pi-клиенте). Это будет отдельный клиент/сеанс, не текущий чат DeepAI Code.
4. Для точного ответа о тарифе/лимитах текущего аккаунта смотреть `Usage → Limits` и официальную страницу оплаты/тарифа DeepAI Code. Баланс PlusVibeAPI к ним автоматически не относится.
5. Отозвать показанный на скриншотах PlusVibeAPI-ключ и выпустить новый; никому не отправлять его в чат.

## Что не удалось подтвердить

- что DeepAI Code принимает API-ключ PlusVibeAPI;
- что DeepAI Code позволяет задавать сторонний Base URL;
- что пополнение PlusVibeAPI увеличит лимит DeepAI или Codex в DeepAI Code;
- что конфиг PlusVibeAPI для Pi непосредственно совместим с DeepAI Code;
- цену конкретной модели или ожидаемое время до исчерпания средств без анализа тарифа и будущей нагрузки.

**Финальный вывод:** на основании доступных скриншотов можно настроить PlusVibeAPI для поддерживаемого API-клиента, но подключить оплату именно текущего чата в DeepAI Code пока не подтверждено. Сначала нужна проверка поддержки custom provider в DeepAI Code либо ответ службы поддержки DeepAI Code.
